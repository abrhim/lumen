# Lumen

Scripture study app. React Router v7 on Cloudflare Workers, Supabase Postgres
(schema `lumen`) reached through Hyperdrive + drizzle, Neo4j for the graph.
pnpm workspace driven by turbo.

```
apps/web              the Worker + UI (routes, components, *.server.ts)
packages/scripture    canon queries, search, tokenizing — the drizzle schema lives here
packages/neo4j-http   graph client
scripts/              one-off migrations, dumps, the verify gate
supabase/             local stack: baseline migration + seed (both GENERATED)
docs/ops/             runbooks
```

## The gate

Before opening a PR, this must exit 0:

```bash
pnpm db:start   # once per session — boots the local Supabase stack
pnpm verify     # typecheck + unit + script tests + Playwright e2e
```

`pnpm verify --no-e2e` while iterating; the full run is ~90s.

**Never point tests at production.** The suite mints real auth users and casts
real roadmap votes, so a misconfigured run is damage, not a failed test.
`verify.sh` refuses to start if any DSN looks non-local — if it refuses, fix the
environment, never the guard. `pnpm db:reset` is the fastest way out of bad
local state.

Read [docs/ops/local-stack.md](docs/ops/local-stack.md) before touching anything
in `supabase/`. Both files there are generated by `pnpm db:regen`; hand-editing
them gets overwritten. Regenerating needs production credentials, so it is a
laptop-only task — it is not part of normal feature work.

## Escalate instead of proceeding

Stop and ask rather than doing these on your own initiative:

- database migrations, or anything under `supabase/`
- auth (`auth.server.ts`, the OAuth legs, RLS policies, GRANTs)
- `wrangler.json`, `.github/workflows/`, dependency changes
- deleting files, or edits spanning more than ~15 files

Merging to `main` deploys to production automatically via
`.github/workflows/deploy.yml`. There is no staging.

## Design

The identity filter for every UI decision: **an application, not a website** —
"Obsidian, but with a spine in holy writ." Land the reader in the reading. No
marketing page.

**Typography first, containers last.** The aesthetic is editorial paper-and-ink:
Fraunces/Newsreader, hairline rules, typographic hierarchy. Actively avoid the
generic AI design dialect — rounded-full pill chips, bordered card rows with
hover-border, uppercase tracked kicker labels on every section, dashed-border
meta tags. Prefer TOC-style ruled text rows over card lists, inline underlined
links over reference pills. `apps/web/app/routes/reader/word.tsx` and the
transcript treatment are the references to imitate.

Go easy on italics and horizontal rules. Both read as chrome when repeated;
tone comes from the ink/muted color hierarchy and from spacing.

**Copy is plain and honest.** Ordinary sentences saying what a thing is and what
it does. No metaphors, no cadence games, no sentence fragments as taglines, no
em-dash pivots for drama. If a line sounds like it is performing, rewrite it.
This applies to every user-facing string, including empty states and hints.

## Gotchas that have cost real time

- **Mobile verification**: headless Chrome lays out at a 500px minimum window
  width and crops the screenshot, so `--window-size=390` fakes an overflow bug
  that does not exist. Drive CDP `Emulation.setDeviceMetricsOverride` instead.
- **Port hygiene**: a dead dev server often leaves a node child holding the
  port, and vite then silently moves to the next one while your tooling keeps
  talking to the stale process. `lsof -nP -iTCP:4179 -sTCP:LISTEN -t` and kill
  what you find. `pkill -f "react-router dev"` misses detached children.
- **Generated vs trigger-maintained columns look identical in the schema.**
  `transcripts.search_vector` is `GENERATED ALWAYS` and rejects any supplied
  value; `verses.search_vector` is written by a BEFORE trigger and is fine to
  carry. Check `attgenerated` before assuming.
- **`information_schema` is permission-filtered.** It will quietly omit grants
  the connecting role cannot see. Read `pg_class.relacl` / `pg_attribute.attacl`
  when grants matter — production uses column-level grants that a naive dump
  silently drops.

## How to work

Work the way you normally would. Don't reach for a prescribed process skill
because a task looks like "a feature" — read the code, make the change, prove it
with the gate. The gate is the discipline; ceremony layered on top of it is cost.

## What you know before you start

`.agent-memory/` (if present) carries the project's accumulated memory —
decisions, dead ends, and things that already cost someone a day. It is copied
in at setup and is not part of the repository. Read what looks relevant before
you begin; it is cheaper than rediscovering it.

`docs/agent-ledger.md` is the shared ledger. Read it first.

When you finish — or fail — append what the *next* agent would have wanted to
know before starting. Not a diary of what you did: the surprises. The thing that
wasn't where you expected. The check that looked green but wasn't. The
assumption this codebase quietly violates.

One entry, dated, a few lines. If nothing surprised you, write nothing. An
honest empty beats filler, and a ledger padded with the obvious stops being
read.

## Conventions

Comments explain *why*, not what, and they earn their place — match the density
of the file you are editing. Tabs, not spaces. Tests live in `__tests__/`
beside what they test; e2e in `apps/web/e2e/`.
