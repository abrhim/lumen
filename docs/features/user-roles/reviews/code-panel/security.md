| SECURITY-1 | high | `apps/web/app/lib/admin-users.server.ts:26,73,129,148,163` | The sort/status/cursor allow-lists are guarded with the `in` operator (`sort in SORTS`, `statusRaw in STATUSES`, `c.s in SORTS`), which walks the prototype chain. `?sort=toString` (or `valueOf`, `constructor`, `__proto__`, `hasOwnProperty`) passes `parseSort` and yields `SORTS["toString"]` = `Object.prototype.toString`, so `S.col`/`S.cast` are `undefined`; `?status=constructor` yields the `Object` function. Both then flow into `sql.raw()` — verified the builder emits `ORDER BY u.undefined DESC` and `WHERE u.function Object() { [native code] } = true`, a guaranteed Postgres error (500). This defeats the *stated + unit-tested* invariant "the allow-list is total" (D6; test `parseSort — the allow-list is total`) and the review's own premise that "every raw fragment is provably from a server-side constant" — the constant lookup is not own-key-guarded. Not exploitable as text injection (the resolved value is a built-in, never attacker text), and `loadUsersPage` is admin-gated, so impact is an admin-triggerable query crash, but the invariant is genuinely broken. | Replace `x in MAP` with `Object.hasOwn(MAP, x)` at all three sites (or make `SORTS`/`STATUSES` null-prototype maps), and guard `const S = SORTS[sort]` so a miss can never reach `sql.raw`. Extend the "allow-list is total" test with a prototype key (`toString`). |
| SECURITY-2 | med | `apps/web/app/lib/admin-users.server.ts:69-81,154,157-158,168` | `decodeCursor` only checks `typeof c.k/c.id === "string"`, not their format, so a valid-shaped cursor with garbage values (`k:"x"`, `id:"y"`) passes decode — the H4b test at `admin.users.test.ts:226` even asserts this returns the cursor, not null. On the default `created` (timestamptz) sort those values feed `'x'::timestamptz` / `'y'::uuid` and Postgres rejects the cast → 500. `loadUsersPage` has no `try/catch`, so the error propagates uncaught; the D6 promise "bad → page-1-never-throws" holds for the decoder but not for the query it produces. Coincidentally, because `headers` are attached only on the success `data(...)` path, a token rotation during such a 500 also drops the admin's rotated Set-Cookie. Admin-only. | Validate cursor values in `decodeCursor` (ISO-date-parseable `k` when the sort is timestamptz; UUID-shaped `id`) and return null on mismatch, or wrap the keyset SELECT in a try that degrades a cast failure to page 1. Add a harness case: valid-shape / invalid-value cursor → page 1, no throw. |
| SECURITY-3 | med | `apps/web/app/routes/scripture.tsx:363-365`, `apps/web/app/routes/book.tsx:30-32` | The F3 fix now attaches the session-commit `headers` (which carry a rotated `sb-*-auth-token` Set-Cookie whenever getClaims refreshed) to a **301** response with no `Cache-Control`. 301 is the most cache-friendly status; a shared/intermediary cache that stores it would replay one user's rotated auth cookie to the next visitor of the same alias URL (session takeover). Cloudflare's default (no-cache when Set-Cookie present) and per-profile browser caches make this latent rather than live, but a token-bearing redirect should not rely on implicit proxy behavior. | Set `Cache-Control: private, no-store` (and ideally `Vary: Cookie`) on these 301s, or downgrade to 302/307 for the auth-carrying path. Only the refresh path carries Set-Cookie, so the common alias hit stays cacheable. |
| SECURITY-4 | med | `apps/web/app/routes/scripture.tsx:363`, `apps/web/app/routes/book.tsx:30` vs `apps/web/app/root.tsx:48-49` | On an alias URL, the root loader **and** the alias loader both run `getSessionUser` in parallel on the same request, each calling `getClaims` with the *same* request refresh token. With an expired access token both attempt an inline refresh concurrently; only the alias's rotated cookie rides the thrown 301 (the root's is discarded by design). This is exactly the "double-refresh regression" the F3 worklist item said to re-verify: two refreshes of one refresh token can trip Supabase reuse-detection and revoke the session — the intermittent silent sign-out F3 set out to fix. Non-alias hits are unaffected (only the alias branch reads the session). | Hoist alias canonicalization above the session read (redirect before any getClaims), or reuse the root loader's already-fetched result instead of a second independent `getSessionUser`. Verify against a real expired-token alias hit that only one refresh fires. |
| SECURITY-5 | low | `apps/web/app/routes/__tests__/admin.users.test.ts:216-245,274-279` | The suite advertises coverage it does not have: `parseSort — the allow-list is total` only tries `"evil"/"sideways"` (never a prototype key, so SECURITY-1 stays green), and H4b only exercises malformed/version/sort-mismatch cursors (never a valid-shape/garbage-value cursor, so SECURITY-2 stays green). The tests give false assurance on precisely the two invariants that are broken. | Add the prototype-key sort case and the garbage-value cursor case alongside the SECURITY-1/-2 fixes so the invariants are actually pinned. |
| SECURITY-6 | low | `scripts/migrate-user-roles.mjs:21-27` | `scrub()` redacts credentials only inside a `scheme://…@` URL or a `password=` query param. A driver/postgres.js error that surfaces host/user/DSN in another shape (bare `user:pass@host`, or a message postgres.js formats without the scheme) would pass through unredacted into the logged `migration_fatal`/`grant_fatal` message. Current prod DSN is `postgresql://…` so coverage holds today; it is a narrow allowlist for a fail path that prints to logs. | Broaden the redaction (also strip a bare `\S+:\S+@\S+` credential pattern), or scrub against the known-secret substring loaded from `.env` rather than pattern-matching URL shapes. |

## Notes (verified clean, not findings)
- **Gate ordering / no bypass:** `requireEntitlement` is the admin loader's first authz statement; anonymous → 404 with `db.execute` never called; non-admin → 404 after only the roles query (no `app_users` query). The fetcher "load more" path hits the same loader, so it is gated identically. Fail-closed on a degraded roles load is correct and both-directions tested.
- **Injection:** all user text (`q`, `role`, cursor `k`/`id`) rides as bound params; ILIKE uses `ESCAPE '\'` with backslash-first escaping (verified `escapeLike("100%_\\x") === "100\\%\\_\\\\x"`). The only `sql.raw` inputs are `SORTS`/`STATUSES` values — safe *once* SECURITY-1 makes the lookups own-key-only.
- **`hasAuthCookie` (F5):** regex correctly matches `sb-*-auth-token(.N)?` and excludes `-code-verifier`; confirmed by execution.
- **Migration/grant invariants:** owner-bypassrls + `security_invoker=false` + negative `lumen_read` auth-USAGE + SELECT-only grants are all asserted post-DDL; grant-role validates email shape, single live user, role existence, and known entitlement keys against the F13 shared source.
