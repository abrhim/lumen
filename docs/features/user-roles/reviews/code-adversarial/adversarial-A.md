## Job 2 — adversarial re-run of the plan's own concerns (what held, what's new)

**Held under attack (verified, not findings):**
- **Backslash-first ILIKE escape, end-to-end:** `escapeLike` doubles `\` FIRST then escapes `%`/`_` (probe: `escapeLike("100%_\\x") === "100\\%\\_\\\\x"`, trailing-backslash input leaves no dangling escape). Compiled clause is `u.email ILIKE $1 ESCAPE '\'` with the pattern riding as bound param `%50\%\_%` — no interpolation, no wildcard injection, `ESCAPE '\'` is a single backslash under standard_conforming_strings.
- **Keyset boundary, email sort:** text keys round-trip losslessly; the big `''`-email (anonymous) tie group pages correctly through the `id` tiebreaker in both directions. Only the timestamptz sorts are broken (CORRECTNESS-1).
- **Fail-closed gate under odd inputs:** `null`/`undefined`/`""` userId 404 without touching the db; a non-array/undefined db, sync throws, non-Error rejections, and NULL array elements from `unnest` all land in the single try → empty set → 404; unknown keys filter-and-log. `hasAuthCookie` (F5) matches chunked/unchunked session cookies and correctly rejects `-code-verifier` (traced the regex against both chunked forms).
- **Cursor decode totality (decode layer):** malformed base64, non-JSON, non-object payloads, wrong version, prototype-key `s` with a mismatched URL sort, and sort/dir mismatches all degrade to null. The totality gap is downstream of decode: value semantics (SECURITY-2) and the `in`-operator lookups (SECURITY-1/CORRECTNESS-2), both already found by the panel and re-confirmed here.
- **Migration/grant invariants:** post-DDL owner-bypassrls + `security_invoker=false` assertions, the negative `lumen_read`-no-auth-USAGE check, SELECT-only grant check (DISTINCT-safe), scrub's last-`@` backtracking, and the DDL↔F13 drift tripwire all check out; suites and typecheck are green.

| ADVA-1 | med | `scripts/migrate-user-roles.mjs:79-81` | The admin-role seed uses `ON CONFLICT (slug) DO UPDATE SET … entitlements = EXCLUDED.entitlements`, so any RE-RUN of this migration (it is advertised as idempotent/converging — "re-run converges it") silently REVERTS `lumen.roles.admin.entitlements` to today's `ARRAY['admin.users']`. ## Stance

The security boundary itself held under attack: the gate runs first and fail-closed in every odd-input shape I could construct, all user text rides as bound params, the backslash-first escape is correct end-to-end in the compiled SQL, and the migration/grant invariants are real checks, not theater. What is broken sits one layer in: the two request-parameter totality holes (prototype-chain `in`, unvalidated cursor values → post-gate 500s) and the µs-truncated keyset cursor (real skipped/duplicated rows across ties — the strongest finding on the list) — all three of which I reproduced independently before reading the panel files, which corroborates the panel rather than merely trusting it. Panel severities are broadly honest; the one correction that matters is SECURITY-4, whose lead fix would reintroduce the F3 dropped-rotation bug — take CORRECTNESS-7's memoization framing instead. Fix-before-ship set: CORRECTNESS-1, SECURITY-1/CORRECTNESS-2, SECURITY-2, CORRECTNESS-6, ADVA-1; the rest are cheap hardening in the same files. The injected tag list was empty — findings were sourced and verified from the panel files on disk.
