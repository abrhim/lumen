## Evidence

All probes run 2026-07-21 against live prod via worktree `.env` DATABASE_URL (`current_user = postgres`), SELECT-only.

- **FK reality (DAT-6):** `pg_constraint` on `lumen.search_index` → one FK, `FOREIGN KEY (collection_id) REFERENCES lumen.collections(id)`, `confdeltype='a'` (NO ACTION). No FK on `ref_id`. Contrast: `lumen.transcripts.episode_id` has `ON DELETE CASCADE` (scripts/migrate-media-collections.mjs:17).
- **Trigger authority (DAT-1):** live trigger defs are `BEFORE INSERT OR UPDATE OF text` (verses) and `BEFORE INSERT OR UPDATE OF name, description` (entities), both `FOR EACH ROW`. Proof the trigger always wins: unshaken ingest explicitly inserts `setweight(...,'A')||setweight(...,'B')` entity vectors (scripts/ingest-podcast/load.mjs:74-76), yet probe found **0 of 65,877** entities with any A/B/C-weighted lexeme (sample `unshaken-25hrVBU3Vz8`: `'come':1 'exodus':4 ...`, all unweighted). Any backfill that writes `search_vector` directly (bypassing the trigger, since `search_vector` is not in the trigger's column list) creates a second expression that can drift; `SET text=text` / `SET name=name` fires the trigger and stays idempotent under re-run.
- **Degree-0 boost collapse (DAT-2, DAT-9):** probe over `lumen.edges` (indexed `idx_edges_from`/`idx_edges_to`): naves_topic 5,319/5,319 degree-0, era 165/165, event 72/572, person 141/3,869, place 91/2,035, symbol 36/480, principle 14/262. With `boost=ln(1+degree)`, `score = 0 × ts_rank` for every naves topic — H10's topics-group ordering would rest on undefined tie order beyond tier 1.
- **Moment staleness (DAT-3, DAT-4):** scripts/ingest-podcast/load.mjs:32-48 — re-ingest deletes the episode entity (cascade wipes transcripts), then deletes only `kind='episode' AND ref_id=$1` from search_index (line 46). Future `kind='moment'` rows for that episode are untouched by design and reference dead seq ranges until the M3 script re-runs; nothing in the plan schedules that re-run. Harness H15 (search-harness.test.ts:129-146) would catch drift only when executed. No current episode id contains `_` (probed), but YouTube ids may — `ref_id LIKE ep||'#%'` is unsafe unescaped.
- **Analyze debt (DAT-7):** `pg_class.reltuples`: verses 41,995, entities 65,877, transcripts 39,459, **search_index -1 (never analyzed)**; `pg_stat_user_tables.last_analyze/last_autoanalyze` NULL for verses/entities/search_index (stats collector reset — n_live_tup shows 0/10/10). Post-M3/M4 search_index jumps ~10 → ~28k rows (5k moments + 20,734 strongs — probed `lumen.strongs_lexicon` count — + artwork) with zero planner stats unless the scripts ANALYZE.
- **KJV variant surface (DAT-5):** probed 1,098 distinct `-eth/-est/-edst` forms in `lumen.words` — the `-est` class is full of non-verb false positives (curation already planned per decision 10); the plan's eval gate checks target-lexeme ≠ variant-lexeme but not closure (target ∉ variant keys), which single-pass `normalize_kjv` requires.
- **Grants (DAT-8):** `pg_default_acl` for schema lumen: `{lumen_read=r/postgres}` — auto-grant applies only to tables created by `postgres`. All six existing lumen tables probed `has_table_privilege('lumen_read', …, 'SELECT') = true`; the invariant keeps that true for `kjv_variants`/`entity_degree` regardless of which admin role runs the script.
- **Visibility premise (DAT-10):** `lumen.collections` probe: all 8 collections including `unshaken` have `public = true` today, while search-harness.test.ts:53 asserts "unshaken (which is public=false + the H8 probe)". `getPublicCollectionIds` will therefore include unshaken for anonymous callers.
- **Ordering dependencies (DAT-8):** `to_regclass('lumen.kjv_variants')`, `to_regclass('lumen.entity_degree')`, `to_regprocedure('lumen.normalize_kjv(text)')` all NULL in prod — M3's dual-indexed moment tsv (plan decision 9) and M4's unaccented strongs projection (H7) hard-depend on M2/M1 objects that do not exist yet; without prechecks a mis-ordered run half-writes `search_index`.
