# Plan — search-endpoint (v2, post-synthesis)

## Tier
**large** — risk axes tripped: public surface (new `/api/search` endpoint + new `@lumen/scripture` exports), data migration (extensions, trigger replacement, new table + indexes, backfills, `search_index` population), behavior change (net-new search capability), cross-system blast radius (`@lumen/scripture` is consumed by the external Ring-2 MCP server). Schema migration + cross-system each independently trigger `large`.

## Goal
Make the full lumen corpus (canon verses, JST, Nave's, Strong's, phase-b entities, artwork, podcast transcripts) actually searchable in Postgres — fixing the four measured content gaps — and expose one typed, federated, visibility-gated `GET /api/search` endpoint. UI is explicitly a later feature.

## Context: live-probe facts (verified 2026-07-21 against prod; panel probes added more)

- Corpus: 41,995 verses · 65,877 entities (8 collections) · 39,459 transcript captions (10 episodes) · 20,734 Strong's lexicon rows · 881k edges. `lumen.search_index` exists (10 `episode` rows) with a designed A/B/C/D projection contract (docs/design/media-collections.md §6).
- **Gap 1 — KJV morphology**: `believeth` doesn't stem ('english' config); believe=551 vs believeth=59, disjoint. Also orthographic classes: shew=358 vs show=175 disjoint; saviour≠savior. Stemmer traps: goes→`goe` but go→`go` (mapping targets must be base forms).
- **Gap 2 — no fuzzy/prefix**: pg_trgm/unaccent/fuzzystrmatch/vector available, not installed. Supabase can't take tsearch dictionary files → in-DB function approach.
- **Gap 3 — transcript granularity**: captions p50=42 chars; phrase queries die at boundaries. Transcript `seq` is contiguous 0-based in all 10 episodes today (probed) — an asserted precondition, not an assumption. 113 caption pairs have overlapping timestamps; numerics arrive as JS strings.
- **Gap 4 — artwork blind**: scenes/characters/themes unindexed in metadata jsonb. Strong's translit is accented (`agapē`, 6,153/20,734 non-ASCII) — FTS can't match `agape` without unaccent at projection time.
- Visibility reality: **all 8 collections including unshaken are `public=true`** — deliberate launch decision 2026-07-21 (human-confirmed at this feature's gate; `public=false` remains the kill switch).
- Grants reality (panel probe): `lumen` schema default ACL auto-grants SELECT to lumen_read for postgres-created tables; **but the `extensions` schema has no lumen_read USAGE** and public-schema function default-ACL omits it — extension functions/operators need explicit schema placement + grants + as-role invariant checks.
- Trigger reality (panel probe): entity/verse vectors are trigger-clobbered on every write (ingest's manual setweight writes were silently overwritten — 0/65,877 entities carry weights). Trigger function definitions DO exist in repo: `setup-triggers-and-rls.sql`, live-verified identical.
- Prod data bugs found by panels: the 10 `search_index` episode payloads are **double-encoded JSON strings**; payload key is `episode` not `episode_id`.
- Runtime consumers of search vectors today: exactly one — `searchScriptures` (Ring-2 MCP). Web app: none. `search_index`: no readers.
- postgres.js: numerics + jsonb can return as strings — coerce at every read site.
- Traffic: solo-dev beta, <1k req/day. Statements on one connection serialize (probed 415ms for 7×~50ms RTT laptop→pooler); Hyperdrive RTT is small but serialization is real.

## Scope

- **In:** M1 extensions; M2 KJV delta-index + weighted vectors; M3 transcript moments + episode-payload repair; M4 artwork/strongs projections + entity_degree; M5 `searchAll` + `/api/search`.
- **Out (deliberate, do not review against):** Search UI; pgvector/semantic; Typesense; MCP server changes/redeploy; rate limiting/KV caching/abuse hardening beyond input validation; ingest/extraction pipeline modifications (M3 is a post-ingest step); Neo4j; in-episode transcript search UX.

## Stage order & shippability

Each stage: own migration script, prerequisite prechecks (`to_regprocedure`/`pg_extension` — exit 2 before writing), COMMIT-gated, invariant-checked, batched, terminal `VACUUM ANALYZE` on touched tables. ## Ring-2 invariant (amended per COR-5/BLA-4)

**Match-set superset; ranking may shift.** The new vector `to_tsvector('english', text) || to_tsvector('english', lumen.kjv_delta(text))` preserves every pre-existing lexeme, so every query that matched before still matches. Because `kjv_delta` emits ONLY the modern replacements of matched archaic/variant words (empty string for fully-modern text), term frequencies are NOT doubled — rank skew is limited to +1 occurrence per archaic word (panel-measured 74% skew under the naive dual-index is avoided). `searchScriptures` LIMIT-N composition may still reorder slightly; M2 logs pre/post top-10 ids for `faith`/`spake`/`believeth` into the migration log as diffable evidence. No MCP change required.

## Design decisions (amended; Δ = changed in synthesis)

1. **Groups & result types (Δ API-4, REL-6)**: groups are keyed `key` ∈ `GROUP_KEYS = scripture|people|places|topics|episodes|art|words` (fixed order); results carry `type` ∈ `verse|jst|person|place|topic|principle|symbol|event|era|summary|episode|moment|artwork|strongs`. `topics` now includes the 1,582 chapter summaries (`type:'summary'`, deep-link to chapter). Excluded: structural entities (book/chapter/volume), strongs_word entities (lexicon projection supersedes). Both enums + key→types mapping exported.
2. **Matching tiers (Δ PER-1/PER-8/REL-7)**: 1=exact (`lower(name)=lower(q)`), 2=prefix `ILIKE q||'%'` (escaped) OR trgm word-similarity via the **`<%` operator** (index-served) with `SET LOCAL pg_trgm.word_similarity_threshold = 0.45` in the group's transaction — never the bare `word_similarity()` function; 3=FTS `websearch_to_tsquery`; 4=trgm fallback when tiers 1–3 yield <3 rows. All ILIKE/trgm interpolations escape `% _ \`. Operator references schema-qualified (`OPERATOR(extensions.<%)`) — lumen_read's search_path lacks `extensions`.
3. **Scoring (Δ DAT-2/COR-4/REL-3)**: within tier, `score = boost * ts_rank('{0.1,0.2,0.4,1.0}', search_vector, query, 1)::float8`; `boost = 1 + ln(1+degree)` (never zero; `LEFT JOIN entity_degree` + `COALESCE(degree,0)`) for people/places/topics, `1 + fame/100` for art, 1 otherwise. **Every group query orders `ORDER BY tier, score DESC, id`** — total order, deterministic pages. No cross-group blending.
4. **Reference short-circuit (Δ COR-6)**: `parseReference(q)` first. Chapter/verse-level parse **that resolves** (found, chapter>0) → return `reference`, skip FTS. Unresolvable parse ("john 99") → `reference:null` + full FTS. Book/volume-level bare name → `reference` AND FTS. `slug-map` humanMatch gains the `chapter>0` guard the slug path already has.
5. **Endpoint contract (Δ API-2/3/4/7/8/9/10)**: `GET /api/search?q&scope&limit`.
   - Validation: `q` trimmed 2–200 chars else 400; `limit` non-numeric → 400, out-of-range → clamped to [1,25] (documented), default 8; `scope` CSV → split/trim/dedupe, empty segment or unknown key → 400.
   - 200 body: `{ query, reference: SearchReference|null, groups: [{ key, results: [{ type, id, title, snippet?, tier, score, payload }] }] }`. `groups` always contains exactly the scoped keys in GROUP_KEYS order, `results: []` when empty (additive-evolution rule documented). `SearchReference = { level, book_id?, chapter?, verse?, verse_id?, display, found }` — parse+existence only, never verse arrays.
   - Snippets: `ts_headline` with `StartSel=⟪, StopSel=⟫, MaxFragments=1, MaxWords=18` — plain text + neutral markers contract; never HTML.
   - Typed payloads (all coerced: parse-if-string jsonb, `Number()` numerics): verse/jst `{verse_id, variant?}`; summary `{book_id, chapter}`; moment/episode `{episode_id, t_start_s?, t_end_s?}` (numbers); artwork `{refs, thumbnail_url}`; strongs `{strongs_no}`. Id stability documented: all ids durable EXCEPT moment ids (response-scoped; deep-link via payload).
   - Errors: JSON `{error, code}` with stable codes (`q_required|q_length|scope_unknown|limit_invalid|internal`) — codes asserted in harness, never message text. 500 never leaks internals; server-side `logEvent('search_failed')` before responding.
   - Every response (200/400/500): `Cache-Control: private, no-store` (house SECURITY-3 pattern).
6. **Visibility (Δ SEC-3/SEC-7)**: route computes `visibleCollections = getPublicCollectionIds(db)` ∪ (ADMIN_COLLECTIONS entitlement → all). `searchAll` requires it explicitly. **Every non-canon source row is collection-gated — including the JST sub-query inside the scripture group** (`'jst' ∈ visibleCollections`). `search_index` rows for kinds moment/artwork/strongs are always stamped with collection_id (migration invariant: zero NULLs); NULL never matches `= ANY($visible)` → fail-closed by construction. Unshaken is public **by deliberate decision** (2026-07-21 launch; human-confirmed) — anonymous search surfacing transcripts is intended.
7. **Query execution (Δ PER-3/COR-1/OBS-2/BLA-2)**: primary path = **one combined statement** (per-group parenthesized subqueries, each with own ORDER/LIMIT, UNION ALL with a group tag) — one round trip. On statement failure: fallback = per-group statements via `Promise.allSettled`; a failed group → `results: []` + `error` in meta; **never 500 from a group failure**. `searchAll` returns per-group meta `{ms, hits, error?}`; the loader logs it (decision 10). Latency: laptop harness asserts <1500ms smoke; the real p95<500ms budget is measured in prod via decision-10 logs, not asserted from a laptop.
8. **Windowing (Δ COR-7/COR-8/DAT-3/DAT-4/BLA-3/BLA-6)**: consecutive captions per episode; flush at ≥~500 chars on gap>2.0s (gap = `max(0, next_start − cur_end)`, Number()-coerced) or sentence boundary; bounds 200–800; tail merges backward. Windows form an exact chain over existing seqs (each window's seq_start = prev seq_end+1; first=min(seq), last=max(seq)) — script asserts source contiguity as a precondition (exit 2 with episode list if violated). `ref_id = episode_id||'#'||seq_start`; **all deletes kind-scoped and keyed `payload->>'episode_id' = $ep`** (never `ref_id LIKE`— `_` is a wildcard and YouTube ids may contain it); one transaction per episode. Ownership rule: `episode`→ingest pipeline, `moment`→build-search-moments, `artwork|strongs`→projections script; each script's invariant asserts other kinds' row counts unchanged. M3 is a **mandatory post-ingest runbook step**; its invariant compares per-episode caption count vs moment coverage and flags stale episodes. M3 also repairs the 10 double-encoded episode payloads and standardizes their key to `episode_id` (SEC-8/API-5).
9. **KJV mapping (Δ REL-1/REL-2/PER-7)**: checked-in `data/kjv-variants.json`; classes: morphology (-eth/-est/-edst + irregulars spake/brake/sware/…) AND orthography (shew*, saviour-class British spellings). Targets are **base forms whose lexeme equals the intended modern query lexeme** (goeth→`go`, not goes→`goe`); eval gate asserts per mapping: target lexeme ≠ variant lexeme AND target lexeme = lexeme of the declared modern query form; closure check (no modern value is a variant key); ambiguous forms dropped (fail-safe retained — PER-7 ruling). `lumen.kjv_variants` DDL: `PK(variant)`, `CHECK variant=lower(variant)`, `CHECK modern<>'' AND modern<>variant`. `lumen.kjv_delta(text)` returns ONLY the mapped modern forms of matched variants (space-joined; '' for modern text) — single-pass, deterministic.
10. **Observability (Δ OBS-1/2/3, PER-5)**: loader emits house `logEvent("search_executed", {q, scope, reference, groups:{key:hits}, zeroResult, elapsedMs, perGroupMs, visibility:'public'|'admin'})`; `search_group_degraded {key, message, ms}` on any group error; `search_failed` on 500. Scripts follow `migrate-media-collections.mjs` conventions verbatim: `COMMIT=1` apply-gate (dry-run default — plan v1's "DRY_RUN=1" wording corrected per OBS-9), JSON events, `invariant_check` per invariant, exit 2 on violation, `scrubSecrets`.
11. **M2 trigger/backfill order (Δ DAT-1/BLA-1/BLA-5)**: (a) `kjv_variants` table + data; (b) `kjv_delta` function; (c) eval gate; (d) capture `pg_get_functiondef()` of both current trigger functions into the migration log; (e) `CREATE OR REPLACE` both trigger functions — **verses**: `to_tsvector(text)||to_tsvector(kjv_delta(text))` (all legs coalesced); **entities**: `setweight(to_tsvector(coalesce(name,'')),'A') || setweight(to_tsvector(coalesce(description,'')||' '||kjv_delta(coalesce(description,''))),'B')` — trigger is the single vector authority; (f) batched backfill via `SET text=text` / `SET name=name` (1–5k rows/tx) so the trigger computes everything; (g) invariants: zero NULL search_vectors, verse floors (believeth≥59, spake≥782, faith≥810), entity floors (shepherd≥233, jerusalem≥1686), believe→john-3-16, shew↔show cross-match; (h) `VACUUM ANALYZE`. Rollback: restore triggers from `setup-triggers-and-rls.sql` (repo, live-verified identical) → drop function → drop table; superset residue in vectors is harmless.
12. **Code placement**: search queries in `@lumen/scripture` (`search.ts`, additive exports); route concerns (session→visibility, validation, HTTP, logging) in `apps/web`. `slug-map.ts` chapter>0 guard is the only existing-file behavior change (Ring-2 note: it only rejects previously-nonsense parses).

## Plan amendments (step 8, implementation-verified — restamped below)

- **A1 (decision 2): trgm predicate is `%` + `word_similarity ≥ 0.45`, not `<%` + SET LOCAL.** `SET LOCAL` is unusable through the `Db.execute` contract (single-statement autocommit; a session GUC through Hyperdrive pooling is also unsafe). The `%` operator is GIN-served at its own default threshold (0.3) as the index prefilter; `extensions.word_similarity(q, name) >= 0.45` refines. The separate tier-4 fallback is subsumed by this predicate. H5 exercises the production form (PER-8).
- **A2 (decision 3): fuzzy-tier scoring uses `GREATEST(ts_rank, word_similarity)`.** ts_rank is 0 for misspelled queries, which tied all tier-2 hits at zero and broke to id order (live-caught: `melchi-1` outranked closer names for q=melchisedek). Similarity now ranks fuzzy hits; exact/FTS hits still rank by weighted ts_rank × boost.
- **A3 (H9 value pin corrected): wildcard-injection pin moved from `mel%`/tier>2 to `z%`→empty.** The original pin encoded a wrong expectation — trgm ignoring `%` as trigram noise IS literal semantics, not injection. `z%` isolates the injection channel: only an unescaped ILIKE could return Z-names.
- **A4 (mechanism): drizzle expands JS array params into tuples — all set-membership predicates use `= ANY(string_to_array(NULLIF($1,''), ','))` (ids are comma-free; empty set → NULL → fail-closed, which H8's closed-visibility leg pins).
- **A5 (typo-adjacent finding, no code change): q=melchisedek now tops `melchisedec-1` — the KJV NT spelling exists as its own phase-b entity alongside `melchizedek-1`. Correct search behavior; the entity-level duplicate is phase-b data debt, recorded for the retro.
