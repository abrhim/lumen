## Notes on lens items investigated and not carried forward as findings

- **`resolveGraphId` fallback on NULL `fe`/`te` for verse endpoints** (backfill-neo4j-collections.mjs:38-42, 160-161): verified correct. `lumen.edges.from_id`/`to_id` have no FK constraint and verse ids never appear in `lumen.entities`, so the `LEFT JOIN` NULL → raw-id fallback matches how verse nodes are stamped directly from `lumen.verses` (line 149) elsewhere in the same script. Not a bug.
- **Chapter id format mismatch (`X-ch-N` vs `X-N`)**: investigated via `scripts/ingest-phase-a.ts:129-130` (`chapterId(bSlug, chapter) => \`${bSlug}-${chapter}\``) and the documented real Neo4j export id in `scripts/backfill-phase-b.ts:233-234` (`LM_Chapter {id:'alma-2'}`). Both sides use the identical `{bookSlug}-{chapterNumber}` format — no systemic `-ch-` infix discrepancy found. The reported 49/1582 dry-run mismatch is therefore very likely a small set of book-slug edge cases, not a wholesale format bug; see CDATA-6 for the logging gap that makes this hard to root-cause today.
