# CODE-PANEL / SPECIALIST — Performance Review: graph-view

Scope: `packages/scripture/src/graph/get-neighborhood.ts`, `apps/web/app/components/graph/{ForceLayout,GraphOverlay,RadialLayout,graph-model}.tsx`, `apps/web/app/routes/scripture.tsx`, bundle/chunk composition.

| ID | Severity | Where | Problem (≤ 25 words) | Fix (≤ 30 words) |
|----|----------|-------|------------------------|-------------------|
| CPERF-1 | High | `packages/scripture/src/graph/get-neighborhood.ts:158-164` | Each layer runs the identical `MATCH (s)-[r]-(n)` traversal twice — once for `count(DISTINCT n)`, once for `collect(n)` — doubling Neo4j read cost per layer, worse on hub verses at depth 3. | Merge into one `CALL{}`: `collect(n)` first, derive `size(matched)` for total and `matched[0..cap]` for the layer — one traversal, not two. |
| CPERF-2 | High | `get-neighborhood.ts:127,175-181` (`GraphOverlay.tsx:344,380`) | `FORCE_NODE_LIMIT` gates only `vm.nodes.length`; the edge-collection subquery has no `LIMIT`, so a dense neighborhood near `totalCap` (600) can return thousands of edges into ForceLayout regardless. | Cap edges too (e.g. `edges[0..N]` server-side) and gate `useForce`/`forceViable` on `vm.edges.length` as well as node count. |
| CPERF-3 | Medium | `GraphOverlay.tsx:350-360` → `ForceLayout.tsx:49-136` | Legend toggle creates a new `filtered` object every click; ForceLayout's effect keys off `[vm, positions]`, so it tears down and rebuilds the whole simulation (alpha=1 restart) and rebinds all N drag handlers just to hide dots. | Split filtering into a separate effect that toggles node/edge `display`/opacity via refs, leaving the running simulation and drag bindings untouched. |
| CPERF-4 | Medium | `get-neighborhood.ts:175-181` | Sibling-edge step does `UNWIND visited (≤600) AS a MATCH (a)-[r]-(b) WHERE b IN visited` — a list-containment check re-evaluated for every relationship found on every visited node's full expansion, no index. | Build `visited` into a Cypher map/set once (or use `apoc.coll.toSet` + hash lookup) instead of repeated `IN` scans over a list. |
| CPERF-5 | Medium | `apps/web/app/components/graph/GraphOverlay.tsx:236-237`; `apps/web/app/routes/scripture.tsx:40` | `GraphOverlay` statically imports both `ForceLayout` and `RadialLayout`; only `GraphOverlay` itself is `lazy()`, no `manualChunks` split exists — so d3-force/drag/selection/zoom ship even to reduced-motion or large-neighborhood users who only ever render the dependency-free `RadialLayout`. | `const RadialLayout = lazy(() => import("./RadialLayout"))` and `const ForceLayout = lazy(() => import("./ForceLayout"))` separately, so d3 only loads when force is actually chosen. |
| CPERF-6 | Medium | `apps/web/app/routes/scripture.tsx:43,1120` | `PENDING_FOREVER` is a module-singleton promise that never resolves; every optimistic graph-open before the loader's real promise commits mounts `<Await resolve={PENDING_FOREVER}>`, and React's Suspense attaches a retry listener that never fires and never frees for the tab's lifetime. | Drive the skeleton off `navigation.state === "loading"` instead of suspending on a fake eternal promise; drop `PENDING_FOREVER`. |
| CPERF-7 | Low | `apps/web/app/components/graph/ForceLayout.tsx:62-64` | `vm.edges.filter(e => vm.nodes.some(...))` is O(E×N) via nested `.some()` scans instead of a Set lookup; re-run on every full effect re-run, including the CPERF-3 legend-toggle restarts. | Build a `Set<string>` of node ids once per effect run and use `.has()` instead of `Array.some()`. |
| CPERF-8 | Low | `apps/web/app/routes/scripture.tsx:206` | `getPublicCollectionIds(context.db)` is an uncached live Postgres query on every graph-panel request, even though the public-collection set "rarely changes" per its own comment; unlike the neighborhood, it isn't wrapped in `cachedJson`. | Wrap in `cachedJson` with a short TTL (e.g. 5 min) keyed on a fixed cache key, same pattern as the neighborhood cache. |
