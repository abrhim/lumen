# CODE-PANEL / accessibility — graph-view

Verifies plan `## Decisions` A11Y-2, A11Y-3, A11Y-4, A11Y-8, A11Y-9 as actually shipped in the diff, against `apps/web/app/components/graph/{GraphOverlay,ForceLayout,RadialLayout}.tsx` and `apps/web/app/routes/scripture.tsx`.

| ID | Severity | Where | Problem (≤ 25 words) | Fix (≤ 30 words) |
|---|---|---|---|---|
| CA11Y-1 | High | `GraphOverlay.tsx:270-291` (`Segmented`) | `role="radio"` buttons have no roving tabindex or arrow-key handling; every option is its own tab stop and Arrow keys do nothing — violates the ARIA radiogroup pattern. | Add `onKeyDown` for ArrowLeft/Right/Home/End moving `aria-checked`/focus, with `tabIndex={-1}` on unselected options (roving tabindex). |
| CA11Y-2 | High | `GraphOverlay.tsx:79-81,198-200,96,141` | `aria-live` spans/paragraphs mount with their final text already present ("Loading graph…", "Graph loaded: N…") instead of appearing empty then being filled — many SRs (NVDA/JAWS/VoiceOver) only announce mutations inside an already-rendered live region, so these likely never fire. | Render the live region once (e.g. in `GraphOverlay`, outside Suspense) empty, then set its text via a `useEffect` one tick after mount/resolve. |
| CA11Y-3 | High | `ForceLayout.tsx:148-179`, `RadialLayout.tsx:42-71` | Default "graph" view's SVG is `aria-hidden` and node recenter is `onClick`-only (no `tabIndex`/`onKeyDown`/role) — keyboard-only sighted users, not just SR users, have zero access to graph interaction, discoverable only by noticing the non-standard "View" radiogroup (CA11Y-1). | Add a visible "Switch to list view for keyboard access" hint near the canvas, or make nodes keyboard-operable directly. |
| CA11Y-4 | Medium | `GraphOverlay.tsx:172-193` (`disabled={isPending}`) | Disabling all three `Segmented` groups while a navigation is pending removes the currently-focused option from the tab order mid-interaction, dropping keyboard focus unpredictably (commonly to `<body>`, fought back into the dialog by Radix's focus scope). | Keep the focused/selected option focusable (e.g. `aria-disabled` + blocked `onClick`) instead of the native `disabled` attribute. |
| CA11Y-5 | Medium | `GraphOverlay.tsx:36-38` vs `161` | Dialog `Title` always reads the raw technical `entityId` (e.g. "Local graph for summary-1-ne-3-7"), rendered outside `Suspense` before data loads, and never updates to the friendly `vm.center.label` shown in the visible `h2` once resolved. | Keep the sr-only Title generic ("Local graph") pre-load, then re-announce the resolved label via the existing `aria-live` region instead of a stale ID. |
| CA11Y-6 | Medium | `ForceLayout.tsx:138-146,177-178` | Hover-dim sets `opacity="0.25"` on the whole node `<g>` (fill + text) for non-neighbors, dropping contrast vs `--paper` from a compliant ~5–7:1 to ~1.4:1 — under the 3:1 non-text minimum and far under 4.5:1 for the still-rendered text labels. | Dim only the connecting edges/rings, or clamp dimmed opacity so blended color stays ≥3:1 (roughly opacity ≥0.55 for these hues). |
| CA11Y-7 | Low | `GraphOverlay.tsx:158-160,214-215,243,319,336` | `--color-faint` (`#9b8e78`) is leaned on throughout the new UI (depth/type labels, ListView section headers, hop-count badges) at only ~2.6–3.2:1 against panel/paper/panel2 — under 4.5:1 required for this 10–11px text. | Swap `text-faint` to `text-muted-foreground` or darken the token for these labels; pre-existing token, but newly load-bearing here. |
| CA11Y-8 | Low | `ForceLayout.tsx:101-120,132-136`; `GraphOverlay.tsx:29` (no `onEscapeKeyDown`) | Escape during an active force-drag closes the whole dialog via Radix's default handler without the drag `end` callback firing; cleanup only calls `sim.stop()`, so d3-drag's window-level move/up listeners aren't explicitly removed. | Override `onEscapeKeyDown` to cancel an in-progress drag first (release `fx`/`fy`, call the drag behavior's `on("end")` path) before letting Escape close the dialog. |
| CA11Y-9 | Low | `GraphOverlay.tsx:217-218` vs `294-356` (`ListView`) | Switching "View" to `list` doesn't move focus into the new region or announce the switch — an SR user must re-discover the freshly rendered content with the virtual cursor. | On `view` change to `"list"`, focus the list container (`tabIndex={-1}` + `.focus()`) or post an `aria-live` "Switched to list view" message. |

Note: `aria-describedby={undefined}` on `DialogPrimitive.Content` (`GraphOverlay.tsx:34`) is intentional/fine — the documented Radix workaround to suppress the missing-Description console warning when there's no real description to give.
