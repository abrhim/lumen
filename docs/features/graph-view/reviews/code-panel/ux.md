# CODE-PANEL / UX — graph-view implementation review

| ID | Severity | Where | Problem (≤ 25 words) | Fix (≤ 30 words) |
|---|---|---|---|---|
| CUX-1 | high | `GraphOverlay.tsx:39-45` (Suspense/Await), `GraphOverlay.tsx:117-120` (`layout`/`view`/`hiddenTypes`/`positionsRef`) | Every recenter/depth-change navigates → loader returns a *new* `graph` promise → `Await` re-suspends → `GraphBody` remounts fresh, resetting `positionsRef`, `hiddenTypes`, `layout`, and `view`. Defeats UX-9. | Lift position map, hidden-types, layout and view state up into `GraphOverlay` (above the `Await` boundary) or `scripture.tsx` so they survive the promise swap. |
| CUX-2 | high | `scripture.tsx:515-524`, `GraphOverlay.tsx:29-52` | UX-10 promised an invoker ref for focus restore; none exists anywhere in the diff. Overlay relies on Radix's implicit `document.activeElement` capture, which is fragile across 3 entry points, especially the mobile Sheet→overlay swap where two dialogs mount/unmount together. | Capture the triggering element's ref in `openGraph`/`graphButton` callers and pass it to `GraphOverlay` for explicit `onCloseAutoFocus` restore. |
| CUX-3 | medium | `GraphOverlay.tsx:204` | Truncation copy always reads "narrow with a smaller depth," even at depth 1 (already the minimum) — an impossible suggestion whenever truncation happens at the default depth. | Omit or vary the depth suggestion when `depth === 1`; keep only "recenter on a neighbor" at that depth. |
| CUX-4 | medium | `ForceLayout.tsx:190`, `RadialLayout.tsx:74` | Persistent recenter ring is `strokeWidth={1}` at `strokeOpacity={0.35}` in the node's own (often muted) color — likely too faint on the parchment background to read as a reliable, non-hover affordance for touch users, the exact gap UX-5 was meant to close. | Raise opacity/width or use a fixed high-contrast ring color instead of the node's own low-saturation type color. |
| CUX-5 | medium | `GraphOverlay.tsx:123-132` (`filtered` useMemo), `ForceLayout.tsx:55-142` (effect keyed on `vm`) | Toggling a legend type filter produces a new `filtered` object identity every time, re-running ForceLayout's whole effect and restarting the simulation at `alpha=1` — a full jarring re-layout for what should be a simple show/hide. | Keep the simulation instance stable across filter changes; add/remove nodes via `sim.nodes()` instead of re-running `forceSimulation()` from scratch. |
| CUX-6 | low | `GraphOverlay.tsx:177,184,191` | `isPending` disables Depth, Layout, *and* View segmented controls together, even though Layout/View are pure client-side state changes unrelated to the in-flight network fetch. | Only disable the Depth control while `isPending`; leave Layout/View interactive. |
| CUX-7 | low | `scripture.tsx:339-342,488` | Closing the graph on mobile (`closeGraph`) navigates back to `?verse=`, which re-opens the bottom Sheet immediately — a full-screen dialog exit followed by a sheet slide-in with no coordinated transition between them. | Either keep this (it correctly follows UX-1's mutual exclusion) or cross-fade the two so the swap doesn't read as a bounce; call out the intent in a comment either way. |

**Note on the lens's other checks:** `?graph` correctly does *not* persist through `readVerse` (`scripture.tsx:343-346`) — confirmed intentional, not a bug. UX-3's disable+dim pairing is present on both axes (Segmented `disabled` + `isPending` overlay dim in `GraphOverlay.tsx:196-198`), just over-scoped per CUX-6. UX-8's legend labels cover every `GRAPH_NODE_TYPES` value returned to neighbors; the `FALLBACK_TYPE`/"Other" path in `graph-model.ts` is effectively dead code for neighbors (only reachable if a non-content-typed node were ever queried as center) and not worth a separate finding.
