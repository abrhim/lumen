# Panel 1 — Performance (frontend + query) review: graph-view plan

| ID | Severity | Where | Problem (≤ 25 words) | Fix (≤ 30 words) |
|---|---|---|---|---|
| PERF-1 | high | `getNeighborhood` Cypher contract (plan §Scope 2); precedent in `packages/scripture/src/graph/explore-graph.ts:86-101` | `[*1..depth]` variable-length MATCH enumerates all paths before `ORDER BY hops LIMIT` truncates — a depth-3 traversal from a 60+-edge hub (`1-ne-3-7`) can explode combinatorially server-side before any cap applies. | Cap traversal itself, not just output: per-hop `apoc.path.expandConfig`/`subgraphAll` with `limit`/`maxLevel`, or iterative single-hop expansion with a LIMIT applied at each layer before the next hop runs. |
| PERF-2 | high | `packages/scripture/src/__tests__/get-neighborhood.test.ts` (harness) | Every test mocks Cypher rows directly (`capturingNeo4j([NEIGHBORHOOD_ROW])`); nothing asserts the emitted Cypher structurally bounds per-hop work. `perDepthCap`/`totalCap` (75/400) could ship as a JS `.slice()` after an unbounded fetch and still pass. | Add a harness assertion on the captured query string (or a live-smoke assertion) that caps are expressed in Cypher (LIMIT per CALL/hop), not only in post-processing. |
| PERF-3 | high | Web overlay force layout, `apps/web/app/components/graph/ForceLayout.tsx` (planned); lens flags "mock re-renders React state per tick" | d3-force default alpha decay runs ~300 ticks to settle; if each tick drives a React `setState`, up to 400 SVG nodes reconcile thousands of times/sec — main-thread jank, worse on mobile. | Drive the simulation off-React: mutate DOM/refs (or `<canvas>`) directly in the tick handler, batch a single React commit only on drag-end/settle, not per tick. |
| PERF-4 | med | Recenter flow, plan §Scope 3 ("Node click recenters... pushed"); known issue already flagged in `apps/web/app/routes/scripture.tsx` | Recenter pushes a full navigation to `?graph=<clicked>`, rerunning the whole `scripture.tsx` loader — Postgres `getVersesByChapter`/`getChapterSummary` refetch even though the chapter is unchanged and only the graph promise should update. | Add `shouldRevalidate` to skip chapter-data refetch when only `graph`/`depth` search params change; keep the graph promise as the only thing that re-resolves. |
| PERF-5 | med | KV cache key `graph:v1:<id>:<depth>:<collections-hash>`, plan §Scope 3; contrast with `CONNECTIONS_TTL_SECONDS` in `scripture.tsx:34` and `cachedJson`'s required `ttlSeconds` param | Plan never states a TTL for graph cache entries (verse-panel cache has an explicit 7-day TTL). Key cardinality (entity × depth × collections-hash, push-based recenter trail) risks low hit rate with no expiry policy defined. | Pick and document an explicit TTL (graph data is as immutable as verse connections — reuse the 7-day constant) before implementation, not left implicit. |
| PERF-6 | med | Node contract `{id, name, labels, collection_id}`, plan §Scope 2; test fixture `NEIGHBORHOOD_ROW.center.name: null` for a Verse | Verse nodes carry no `text`/`reference`, and `name` is `null` for Verse entities per the harness fixture — graph nodes for verses render with no visible label unless the client derives one from `id`. | Derive a display label client-side via the package's existing reference parser (`parseReference`), or add a cheap computed `reference` field to the node shape — don't leave it to render blank. |
| PERF-7 | med | Layout selection, plan §Scope 3 ("radial layout as deterministic fallback and the `prefers-reduced-motion` default") | Layout choice only branches on `prefers-reduced-motion`, not on resulting graph size — a 400-node/depth-3 result runs the same physics + drag/zoom handlers on a low-end phone as it does on desktop. | Add a node-count threshold (e.g. >150 nodes or mobile viewport) that also falls back to the radial layout, independent of the motion preference. |
| PERF-8 | low | Lazy chunk, plan §Files touched (`d3-force`, `d3-zoom`, `d3-selection`, `d3-drag`, Q6 "~35kb lazy chunk") | The one `React.lazy` chunk bundles the full physics stack even for requests that end up rendering the non-motion radial fallback, which doesn't need `d3-force`/`d3-drag` at all. | Split `RadialLayout.tsx` into its own smaller lazy chunk so `prefers-reduced-motion` / low-power paths skip downloading the force/drag/zoom bundle entirely. |
| PERF-9 | low | `collections` param, plan §Scope 6 (defaults to "all-public collections") | No stated cap on the size of the `collections` list bound into Cypher; an unbounded `IN`-style parameter list on every default (no-filter) query adds planner cost that grows with collection count over time. | Document/enforce a small max collection-id count for the default filter, or resolve "all public" server-side to a single boolean/label check instead of an ID list. |
