# Security review — graph-view (PANEL-1)

| ID | Severity | Where | Problem (≤ 25 words) | Fix (≤ 30 words) |
|---|---|---|---|---|
| SEC-1 | high | `get-neighborhood.ts` depth 2–3 traversal, modeled on `explore-graph.ts` `[*1..depth]` | Cypher pattern labels only bind path endpoints; a variable-length hop can silently route through KB_*/DS_* tenant nodes mid-path, and FM-8's disjunctive assertion (any `labels()` clause OR no bare `(x)`) doesn't prove every hop is constrained. | Require `WHERE ALL(x IN nodes(path) WHERE any(l IN labels(x) WHERE l IN $lmLabels))`; strengthen FM-8 to assert per-hop, not just endpoint, constraints. |
| SEC-2 | high | `get-neighborhood.ts` depth=1 branch vs. `explore-graph.ts:49-51` | `explore-graph.ts`'s depth=1 query (`MATCH (n {id}) OPTIONAL MATCH (n)-[r]-(connected)`) is fully unlabeled; plan cites it as reference but doesn't forbid reuse — copying it leaks any-layer neighbors. | Write depth=1 fresh with the same `{Label}` constraint as depth 2-3; add an explicit depth=1 cross-tenant harness case. |
| SEC-3 | med | Query building for `truncated.total` count | Plan doesn't state whether the total-count subquery carries the same label/collection constraints as the main return; an unconstrained `COUNT` would leak the size of other tenants' graphs via `truncated.total`. | Apply identical `{Label}` and collection constraints to the count subquery; add a harness case asserting `total` excludes non-LM nodes. |
| SEC-4 | med | `packages/neo4j-http/src/layers.ts` `validateLayerQuery` | Guard strips `[:A\|B]` relationship-type patterns before scanning for raw labels, so it gives zero defense-in-depth against unsanitized `relTypes`; the manual allowlist in `getNeighborhood` is the only backstop. | Add a client.ts-level check that rel types inside `[: ]` come from a passed allowlist, mirroring the label guard. |
| SEC-5 | med | Web loader KV key `graph:v1:<id>:<depth>:<collections-hash>` | Plan doesn't define how `collections-hash` is computed; a naive join/hash can collide across different collection sets (e.g. `['a','bc']` vs `['ab','c']`), serving one caller's cached result to another. | Hash a sorted, delimiter-safe (e.g. `sha256(JSON.stringify([...collections].sort()))`) representation in the cache key. |
| SEC-6 | med | `getNeighborhood` opts `collections?: string[]`; consumed by web + MCP (`packages/scripture` "shared by web + MCP" per plan) | No server-side check ties `collections` to the caller's `owner_id`/`public` row in Postgres `lumen.collections`; function accepts caller-asserted IDs as-is. Once user collections land, any caller (including the live MCP tools) passing a private collection id gets served. | Contract must require a pre-validated/resolved collection list (checked against Postgres ownership) be passed in — never accept caller-asserted arbitrary IDs; record as a blocking dependency for the collections feature. |
| SEC-7 | med | `explore-graph.ts:48-66` depth=1 pattern (reference for new query) | Depth=1 fan-out has no Cypher-level `LIMIT` (only depth>1 has `LIMIT 50` inside `CALL`); a hub node's `collect()` can materialize/transfer an unbounded row set before app-side truncation ever runs. | Apply `perDepthCap`/`totalCap` as Cypher `LIMIT` in every depth branch, not only post-fetch JS truncation. |
| SEC-8 | med | `getNeighborhood` opts `perDepthCap?`, `totalCap?` | Plan states depth gets a hard Zod 1-3 bound but doesn't state any bound on `perDepthCap`/`totalCap`; if either is ever caller-suppliable (web query param or MCP arg), an oversized value defeats the DoS protection the caps exist for. | Zod-bound `perDepthCap`/`totalCap` server-side to a hard ceiling (e.g. ≤75/≤400); never let caller input exceed it. |
| SEC-9 | low | `scripts/backfill-neo4j-collections.mjs` (new, unwritten) | Plan doesn't state whether ids/collection_id matched against Neo4j are bound Cypher params or string-built; some ids originate from `phase-b`/`anthropic-batch` (AI-generated, less trusted) entities per `ingest-phase-a.ts` seed collections. | Require `UNWIND $rows` with bound parameters for all id/collection_id values in the backfill's Cypher; never string-interpolate. |
| SEC-10 | low | `scripts/backfill-neo4j-collections.mjs` secrets handling | Script reads `.dev.vars`/`.env` for Neo4j+Postgres credentials (cf. `ingest-phase-a.ts` `DATABASE_URL` pattern); plan doesn't specify redaction for `--dry-run` output or thrown errors, which could echo a connection string containing a password. | Never log raw `DATABASE_URL`/Neo4j URI/password; scrub credentials from any console output or error message before printing. |
