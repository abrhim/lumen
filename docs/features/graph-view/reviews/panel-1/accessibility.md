# Panel 1 — Accessibility Review: graph-view

| ID | Severity | Where | Problem (≤ 25 words) | Fix (≤ 30 words) |
|---|---|---|---|---|
| A11Y-1 | high | Plan scope; mock `GraphCanvas` nodes (lines 566-570) | No keyboard navigation strategy for graph nodes anywhere in plan; mock nodes are `<g onClick>` with no `tabIndex`/`role`/keydown handler. | Specify roving-tabindex node list with arrow-key traversal to neighbors, Enter to recenter, in Files-touched/Public-contract before build. |
| A11Y-2 | high | Plan Scope + Public contract | The graph IS the content but no non-visual equivalent is planned — no structured list of the same neighborhood data for screen-reader users. | Add a visually-hidden (or togglable) list view of nodes/edges per depth, sourced from the same `getNeighborhood` result, as in-scope deliverable. |
| A11Y-3 | high | Public contract line 48; mock `.lm-reader-ov` (line 612) | Plan claims "focus trapped and restored" but `GraphOverlay.tsx` isn't specified to reuse the existing Radix Dialog (`sheet.tsx`); mock overlay has zero `role`/`aria-modal`/Esc-keydown. | Build `GraphOverlay` on the same Radix `Dialog`/`Sheet` primitive already used in `scripture.tsx`; add an explicit harness assertion for focus trap + restore. |
| A11Y-4 | med | Mock depth/layout segmented controls (lines 622-633) | Depth (1-3) and Layout (radial/force) toggles are plain buttons with a `.on` class only — no `aria-pressed`, `role="radiogroup"`, or `aria-selected` anywhere in the component. | Implement as `role="radiogroup"` with `aria-checked`/`aria-pressed` per button, or use Radix `ToggleGroup`/`RadioGroup` primitives. |
| A11Y-5 | med | Mock node fill logic (`colorOfCol`, lines 840-847); legend (line 609) | Node type is encoded only by fill color on the canvas itself (e.g. principle `#b07d2b` vs person `#2f6f5e`); legend has text but nodes don't reference it directly. | Add a per-type glyph/icon or stroke pattern inside each node circle, not just canvas fill color, so type is legible without color. |
| A11Y-6 | med | Mock `rad(n)` (line 560): depth-2 radius 13px | Depth-2 node hit target is a 26px-diameter SVG circle with no padding/invisible hit-slop — borderline against WCAG 2.5.8, tight on the mobile sheet entry point. | Keep visual radius but wrap each node in a larger invisible circle (≥24px, ideally 44px) as the actual click/tap target. |
| A11Y-7 | med | Scope item 3 (d3-zoom/d3-drag); plan line 25 | Force layout adds pointer-only pan/zoom (`d3-zoom`/`d3-drag`, files-touched list) with no keyboard equivalent specified — keyboard-only users (not just reduced-motion users) can't pan/zoom at all. | Add keyboard zoom (+/− or Ctrl+scroll equivalent keys) and arrow-key pan, independent of the reduced-motion default. |
| A11Y-8 | med | Public contract + Failure modes (lines 44-59) | No `aria-live` region planned for async load completion, truncation ("showing 50 of 213"), or the degraded-mode notice — all described as visual states only. | Add a polite `aria-live` region announcing load-complete, truncation counts, and degraded/not-found states when the overlay opens. |
| A11Y-9 | low | Mock node colors, e.g. `xverse` `#9b8e78` at `fillOpacity: 0.55` (line 568) on `--paper` background | Non-text contrast of node fills/strokes against the parchment paper background isn't verified; low-opacity fills (0.55) are likely to fail WCAG 1.4.11 (3:1 non-text contrast). | Run contrast checks for every node-type color at both full and 0.55 opacity against `--paper`; adjust palette or drop opacity dimming for accessibility mode. |
