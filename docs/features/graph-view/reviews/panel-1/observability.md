# Panel 1 — Observability review: graph-view plan

| ID | Severity | Where | Problem (≤ 25 words) | Fix (≤ 30 words) |
|---|---|---|---|---|
| OBS-1 | high | FM-1, web overlay loader | Plan never names the log event/fields for a degraded graph fetch; risks silently reusing `neo4j_degraded` with no entity/depth/collections context. | Emit `graph_degraded` (distinct event) with `entityId, depth, collections, error.name, error.message, elapsedMs`. |
| OBS-2 | high | Backfill script | Script only "reports stamped/missing counts" at the end; no per-batch progress or crash-point logging for a one-shot prod migration that IS the audit trail. | Log one structured line per batch (`batch, offset, stamped, skipped, missing, cumulative`) plus a final summary; redirect stdout to a persisted file, not just terminal. |
| OBS-3 | med | FM-6 fail-open path | "Counted and logged" for edges missing `collection_id` is undefined: unclear if logged per-request (noisy, high cardinality) or only once in backfill. | Log the missing-`collection_id` count once per backfill run (not per graph request); runtime queries should silently include, no per-request log. |
| OBS-4 | med | Cache key `graph:v1:<id>:<depth>:<collections-hash>` | Collections are hashed into the key with no logged mapping from hash → collection set, making cache entries undebuggable in prod. | Log the hash algorithm/input list once at cache-key construction (debug level) or log `{hash, collections}` on cache-miss writes. |
| OBS-5 | med | FM-2, depth-3 caps | No mechanism to observe cap effectiveness in prod — `truncated.shown/total` is only asserted in tests, never logged live, so silent over-truncation on hub entities goes unnoticed. | Log `truncated.shown, truncated.total, depth, entityId` on every `getNeighborhood` resolution (or sampled) to build a truncation distribution. |
| OBS-6 | med | Web overlay (client) | d3-force simulation crashes / GraphOverlay render failures are entirely invisible — no client error boundary or reporting exists, and the plan doesn't say this is out of scope. | State explicitly in scope/out; at minimum wrap overlay in an error boundary that logs via a `navigator.sendBeacon`/fetch to a minimal endpoint, or explicitly defer with rationale. |
| OBS-7 | med | FM-3, entity not-found | Unknown entityId resolves to `{found:false}` with no HTTP 404 and no log line (unlike `scripture_404`), so broken/stale entity links are invisible to ops. | Add `logEvent("graph_not_found", { entityId })` alongside the `{found:false}` resolution, mirroring the `scripture_404` pattern. |
| OBS-8 | low | FM-4/FM-5, allowlist rejection | Depth/relType/nodeType validation failures are silently clamped/rejected with no log signal, losing visibility into malformed clients or probing traffic. | Log a low-volume event (e.g. `graph_param_rejected`) on clamp/reject with the offending raw value and reason. |
| OBS-9 | low | Backfill idempotency (FM-9) | Re-run reports "0 new properties, exit 0" but no run metadata (who/when/dry-run flag) is logged, weakening the audit trail this script is meant to provide. | Stamp each run's summary line with `timestamp, dryRun, invokedBy` (env/user) for later audit reconstruction. |
| OBS-10 | low | KV cache reuse | `cachedJson` already logs `kv_cache_error` for get/put failures (op, key) — plan doesn't confirm graph reuses this helper as-is, risking a bespoke/undocumented cache error path. | Confirm `getNeighborhood`'s cache wrapper reuses `cachedJson`/`log.server.ts` unchanged; no new cache-error logging contract needed if so. |
