# Code panel / specialist — migration safety — canon-spine

Lens: operational safety of running `migrate-canon-spine.mjs`,
`ingest-words.mjs`, `smoke-canon-spine.mjs` against prod, pre-execution.
Verifies the synthesis promises (MIG-2, MIG-4, MIG-8, exit codes, `sql.begin`
+ `tx.unsafe(SPINE_DDL)` semantics, words-ingest batching, `--book` handling,
smoke's P3-marker write) against the actual implementation, not the plan text.

| ID | Severity | Where | Problem (≤ 25 words) | Fix (≤ 30 words) |
|---|---|---|---|---|
| CMIG-1 | Critical | `migrate-canon-spine.mjs` `SPINE_DDL` L95-96 (`DROP TABLE IF EXISTS lumen.words; CREATE TABLE lumen.words`) | Unlike every other DDL statement (all `IF NOT EXISTS`), P1's DDL unconditionally drops+recreates `words`. A second plain P1 run after `ingest-words.mjs` has populated data destroys all ingested word rows. | Change to `CREATE TABLE IF NOT EXISTS lumen.words (...)`, matching the idempotent pattern used everywhere else in `SPINE_DDL`. |
| CMIG-2 | High | `migrate-canon-spine.mjs` L156-157 (P4 marker check) | Plan promised P4 gated on "marker + human confirmation" (MIG-8), but the code only checks the persisted marker — no interactive prompt or `--confirm` flag before the live, irreversible `DROP COLUMN` runs. | Require an explicit `--confirm`/typed-phrase flag or interactive y/N prompt in addition to the marker before non-dry-run P4 executes. |
| CMIG-3 | High | `migrate-canon-spine.mjs` L66 / `ingest-words.mjs` L47 (`loadAdminUrl`, `/:6543\b/.test(url)`) | Regex only rejects the literal string `:6543`. A URL with no port, or a transaction-mode pooler intentionally served on 5432, passes unchecked and silently breaks multi-statement DDL/tx semantics mid-run. | Add a runtime probe: session-level `SET`/`current_setting` round trip across two top-level statements (not `BEGIN;SET LOCAL`, which behaves identically under both pooling modes); abort if the value doesn't persist. |
| CMIG-4 | Medium | `ingest-words.mjs` L37-38, L55-57 (`--book` flag) | `onlyBook` is used as `[{ id: onlyBook }]` with no existence check against `lumen.books`; a typo'd/unknown book id silently produces a 0-verse, 0-token batch and exits 0. | Before the loop, `SELECT 1 FROM lumen.books WHERE id = ${onlyBook}`; throw/exit 1 if it doesn't resolve, instead of a silent no-op success. |
| CMIG-5 | Medium | `migrate-canon-spine.mjs` L156 vs L158 (P4 marker check vs `sql.begin`) | The `canon-spine-p3-verified` marker SELECT runs outside any lock/transaction before `sql.begin`; a marker deleted or rewritten between the check and the `DROP COLUMN`s goes unnoticed (TOCTOU). Trivial today under the single-runner constraint, but unguarded. | Re-select/assert the marker inside the same P4 transaction immediately before the `DROP COLUMN` statements, not only before `sql.begin` starts. |
| CMIG-6 | Low | `ingest-words.mjs` — batching (`VERSES_PER_BATCH=75`, `sql.begin` per batch, plus per-book `SELECT`) | The "~560 batches × 2 round trips" estimate omits `sql.begin()`'s own BEGIN/COMMIT round trips (4 RTs/batch, not 2) and the ~66 per-book verse-fetch queries; real round-trip count is closer to ~2,300, roughly double what's implied. | Restate the estimate as ~2,300 round trips (BEGIN+DELETE+INSERT+COMMIT per batch + per-book selects); re-time against a real session-mode connection before the prod run. |

If misconfigured with a restricted role, the P3-marker `INSERT` (L90-93) fails with a generic permission error folded into the same `failures` counter as real invariant failures — indistinguishable in output. | Add the same session-mode assertion used by the other two scripts, and log the marker-insert failure with a distinct `event`/message from invariant check failures. |

## Verified — no defect found

- `sql.begin(async tx => { ...; if (dryRun) throw ... }).catch(...)` (MIG-4): throwing inside the callback does trigger a real `ROLLBACK` before the promise rejects — the sentinel path genuinely rolls back, and non-sentinel errors correctly rethrow to the outer catch (`exitCode = 1`). Dry-run exits 0 on full pass, 1 on any invariant failure — the `finally { process.exit(exitCode) }` path is consistent in both P1 and P4, dry-run and live.
- `tx.unsafe(SPINE_DDL)` (multi-statement DDL/DML/GRANT/CREATE POLICY) with no interpolated params goes through postgres.js's simple-query protocol, which supports multiple `;`-separated statements in one batch and runs correctly inside the already-open `sql.begin` transaction; `CREATE POLICY`/`GRANT` are ordinary transactional DDL, no issue.
- `DELETE FROM lumen.words WHERE verse_id IN ${tx(batch.map(v => v.id))}` is the correct postgres.js idiom for an `IN (...)` list; `batch` is never empty when this runs (`planWordBatches` never yields empty batches), so no empty-`IN` edge case is reachable.
- Smoke persisting the P3 marker via `INSERT ... ON CONFLICT` on `lumen.migration_state` needs `INSERT`, which `lumen_read` is never granted (`SELECT`-only per `SPINE_DDL`'s `GRANT`); smoke uses the same admin `.env` `DATABASE_URL` as the migration script, so the write itself is legitimate — the only gap is the missing DSN validation (CMIG-7).
