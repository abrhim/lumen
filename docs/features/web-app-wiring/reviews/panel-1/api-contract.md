| API-1 | high | `GET /scripture/:book/:chapter` | `parseReference` accepts `1-ne`, `1 nephi`, `1 ne`, `1ne` as equivalent book slugs; plan renders all of them 200 instead of canonicalizing to one URL. | On non-canonical book slug, 301/308 redirect to canonical `bookId` slug (e.g. `1ne` → `1-ne`) before rendering; only accept exact `BOOK_SLUGS` canonical values as 200. |
| API-2 | high | URL structure | PRD (`PRD.md` §URL Structure) specifies `/study/:bookId/:chapter#v7`; plan uses `/scripture/:book/:chapter?verse=N`. Path segment and verse-selection mechanism both diverge from the documented contract. | Reconcile with PRD before shipping — either update PRD or plan; picking `?verse=` now and `/study` later means a breaking rename. |
| API-3 | med | `?verse=N` cross-ref panel | Query param controls server-rendered panel content (SSR loader reads it), but verse selection is presentation state, not a resource identifier — makes `/scripture/1-ne/3` and `?verse=7` cache/share inconsistently vs PRD's fragment approach. | Confirm intentionally: if verse selection should be crawlable/shareable and cacheable per-verse, keep query param and document divergence from PRD's `#v7`; else move to fragment. |
| API-4 | high | Loader data shape | `verses: {id, verse_number, text}[]` omits `reference` field the graph layer already returns (`find-cross-references.ts` `CrossReference.reference`, and existing test mock `mockVerses` includes `reference`). Deferred `/scripture/:book/:chapter/:verse` route will need it. | Add `reference` to verse shape now; avoids reshaping loader data (a breaking change for consumers) when verse-detail route ships. |
| API-5 | high | Error semantics | Plan collapses three distinct failure causes — unknown book, non-numeric chapter, chapter with zero verses — into a single 404 with (implied) generic body. No distinction between "book doesn't exist" and "book exists, chapter out of range." | Keep 404 status (correct per REST/SEO) but ensure body/message differentiates cause for debuggability; log which validation branch fired. |
| API-6 | med | Invalid `?verse` handling | "Invalid/missing ?verse → chapter renders without panel (no error)" applies to non-numeric AND out-of-range verse numbers alike (e.g. `?verse=99999` on a 10-verse chapter) — silently returns wrong-looking success. | Fine for malformed input, but consider whether an out-of-range verse number for a valid chapter should still 200-silent or redirect to canonical `?verse=` omitted. |
| API-7 | med | Neo4j degraded response | "Neo4j unavailable → 200, graphDegraded: true" is correct (partial content, don't fail hard), but plan doesn't say whether HTTP is cacheable/CDN-cached in that state — degraded response could get cached and served long after Neo4j recovers. | Add `Cache-Control: no-store` (or short max-age) on responses where `graphDegraded: true` to prevent caching a degraded page. |
| API-8 | med | KV cache key `xrefs:{verseId}` | Cache key correctly uses canonical `verseId` (via `buildVerseId`), but plan doesn't state whether cache key/URL path share the same canonicalization — if `book` param isn't canonicalized (API-1), two URLs could populate/read the same KV key inconsistently under race. | Canonicalize `book` param to `bookId` before building `verseId`/cache key and before any URL-derived comparison. |
| API-9 | low | Volume/book index (`/`) | Plan says books "each link to chapter 1" but doesn't specify the link target format (`/scripture/gen/1` canonical slug vs whatever's in DB) — risk of home page generating non-canonical links if book id source differs from `BOOK_SLUGS` canonical set. | Explicitly state home page links use canonical `bookId` (same source as `verses.book_id`), not display names. |
| API-10 | low | PG unavailable → 500 | Plan states "error boundary (500)" but doesn't specify whether this 500 is cacheable-by-default at the CDN/Worker edge, which could turn a transient outage into a prolonged one. | State explicitly: 500 responses must not be cached (add `Cache-Control: no-store` in error boundary path). |
