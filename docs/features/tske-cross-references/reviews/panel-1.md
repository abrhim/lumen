| COR-1 | Critical | FM-3, in-tx invariant (plan.md:106-107); smoke spot-checks (plan.md:71-72) | Invariant only checks the id *exists*; KJV vs. OpenBible off-by-one versification (Psalm titles, 3 John 14/15, Rev 12:17/18) can map to a real but *wrong* existing verse, silently, never counted as unmapped. | Add distribution/spot-check assertions for known-drift books (Psalm titles, 3 John, Rev 12) in smoke.mjs; can't rely on the unmapped cap alone. |

## data-integrity
| ID | Severity | Where in plan | Problem (≤ 25 words) | Fix (≤ 30 words) |
|---|---|---|---|---|
| DATA-1 | Critical | Scope §2 Ingest: "delete-collection-then-insert in batched transactions" | Batched (multi-commit) delete+insert leaves prod cited-by/references half-populated or empty mid-run; a crash mid-batch stalls the DB in that state with no resume marker. | Wrap the full delete+insert in one transaction, or add an advisory lock plus a resumable batch marker so partial failure never serves half-empty results. |
| DATA-2 | High | Scope §2 Ingest; Failure mode #10 (idempotency) | No dedup of (from_id,to_id) pairs from overlapping/duplicate source rows; `lumen.edges` has no PK/unique constraint, so duplicates insert silently and double-count votes. | Add a unique constraint (or ON CONFLICT DO NOTHING) on (from_id,to_id,rel_type,collection_id), or aggregate/dedupe pairs before insert. |
| DATA-3 | High | Failure mode #3; Live smoke §5 | Ingest invariant only resolves ids against `lumen.verses`, and the plan never re-runs the existing all-collection `smoke-canon-spine.mjs` six-source orphan gate after ingest. | Add explicit deploy step: re-run `smoke-canon-spine.mjs` post-ingest to confirm the existing zero-orphan invariant still passes across all edges. |
| DATA-4 | Medium | Scope §2 Ingest (range expansion) | Self-referencing edges (verse citing itself) from overlapping ranges or raw source rows aren't filtered; no from_id=to_id check is mentioned. | Add an in-tx invariant counting/rejecting from_id=to_id rows, reported and capped like the unmapped-row check. |
| DATA-5 | Medium | Scope §2 Ingest ("openbible collection row") | Collection row creation/upsert semantics are unspecified; a plain INSERT on re-run could violate the idempotency guarantee claimed for edges (FM-10). | Specify `ON CONFLICT (id) DO UPDATE` for the collection row, matching the edges' delete-then-insert idempotency. |
| DATA-6 | Medium | Scope §2 Ingest (`metadata: {votes, ...}`) | Votes live in untyped JSONB; ORDER BY relies on a runtime cast with no supporting index, and a malformed vote value could fail the whole query. | Use a typed `votes INT` column (or validate/cast strictly at ingest) instead of casting `metadata->>'votes'` at query time. |
| DATA-7 | Low | Public contract: "~600k rows ... no schema DDL" | ~600k-row insert (2.4x current 253,499 rows) assumes existing from_id/to_id indexes suffice; no composite (collection_id, from_id/to_id) index is confirmed for the new per-collection query pattern. | Verify/add composite indexes on (collection_id, from_id) and (collection_id, to_id); check the query plan post-ingest before shipping. |
