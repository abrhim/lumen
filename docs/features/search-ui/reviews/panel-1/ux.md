# Panel-1 / UX review — search-ui plan

Lens: copy + states + latency. Plan reviewed: `docs/features/search-ui/plan.md`. Harness read: `search.loader.test.ts`, `api-search-cursor.test.ts`, `search-cursor-harness.test.ts`. Shipped code read: `api.search.tsx`, `packages/scripture/src/search.ts`. Design language read: `scripture.tsx`, `media.tsx`, `AppMenu.tsx`, `root.tsx`. Mockup source read: `build-mockup.py`.

## Findings

| ID | Severity | Where | Problem | Fix |
|----|----------|-------|---------|-----|
| UU-1 | high | plan.md:25; build-mockup.py:271-280 (`.gmore-top` + `.gmore`) | "More in X →" shows whenever a group has ≥4 results (mockup's hardcoded threshold), not when the group is actually truncated. Live probe (`q=faith&limit=8`) shows `places` returning exactly 4/4 (nothing more exists) alongside `scripture/people/topics/episodes/art/words` returning exactly 8/8 (the limit — genuinely truncated). Under the mockup's rule both get an identical "More" CTA, and the CTA is duplicated (header pill + bottom link) for the same group. | Gate the pill/link on `results.length === limitPerGroup` (the same signal `nextCursor` already uses), and keep only one of the two duplicate CTAs. |
| UU-2 | high | plan.md:69 (Q4); search.loader.test.ts:69-73 | Bare `/search` (no `q`) is a realistic, reachable state — not just a cold-start edge case (reached by clearing the input while already on the page, back/forward, or a bare bookmark) — and nothing in Scope, the failure modes, or the harness specifies what renders below the header. As written it can read as a dead page for a reader-first entry surface. | Define explicit empty-query content (inviting copy / example queries), distinct from the zero-results state; add a harness assertion pinning it. |
| UU-3 | high | plan.md:17,25; build-mockup.py:84-90 (`.scope` CSS — no strike/exclude class), 268-270 (`render()` — scope `<a>`s are plain in-page anchors, no click-to-exclude listener anywhere in the script) | The plan calls click-to-exclude "the only cull affordance we ship now," but the "human-approved" mockup never implements it — no struck/faint visual exists, and there is no restore-all when multiple groups are excluded (only implied one-at-a-time re-toggle). The plan's binding visual decisions (Fraunces headers, icons, More-pill, selbar marks) do not cover this interaction at all. | Spec the struck/faint treatment and a one-click "restore all" (shown once ≥2 groups are excluded) before implementation; pin in the F7 harness. |
| UU-4 | high | plan.md:23-26 ("skeleton only after 300 ms"); search.loader.test.ts (no live-typing test exists) | Whether editing the query on `/search` itself live-updates results per keystroke (as the mockup demos, note at build-mockup.py:180-182) or requires Enter is unspecified in Scope, the failure-mode list, and the Open Questions — yet it is the core interaction model of the page. | Add an explicit decision (Q6) + failure mode: debounce ms, URL-update strategy (replaceState vs push), and back-button behavior. The mockup's live-typing note is descriptive of the demo harness, not a ratified default for the real SSR-loader page. |
| UU-5 | medium | plan.md:24,37 (`SearchModal.tsx`, singular, no mobile variant); AppMenu.tsx:158-176 (Popover/Sheet split on `useIsMobile`); media.tsx:811-853 (same Sheet idiom) | The plan specifies one "minimal modal" with no mobile treatment, diverging from the app's established `isMobile`-gated bottom-Sheet idiom used everywhere else interactive chrome opens (AppMenu, media.tsx rails). A plain centered modal on mobile also reads closer to generic AI-workspace chrome than the reader idiom. | Mount-gate `SearchModal` to a bottom Sheet on mobile (mirroring AppMenu/media.tsx), center modal on desktop; add the split to Files touched. |
| UU-6 | medium | build-mockup.py:84-90 (`.scope a` — 14px text, no hit-box); AppMenu.tsx:149-150 (documented 44px "Emil touch rule" via `after:-inset`) | The scope-line exclude gesture — the app's one shipped "cull" affordance — has no touch-target sizing, unlike other interactive controls in the codebase that explicitly carry a 44px hit box. | Apply the same `after:-inset` touch-target pattern already used on AppMenu's trigger to each scope-line item. |
| UU-7 | medium | build-mockup.py:166 (persistent `<kbd>` hint row); product context (reader-first, "do not push this page toward a workspace") | The "`/` · `↑↓` · Enter" hotkey hint is always visible, including on touch devices where none of those keys apply (no physical `/`, no `⌘K`), and before any rows exist to navigate — reading as exactly the research-tool chrome the product brief says to avoid. | Hide/replace the hotkey hint on touch-only viewports (same matchMedia gate as `useIsMobile`); only surface the `↑↓`/Enter portion once rows exist. |
| UU-8 | low | plan.md:26 (F5); search-cursor-harness.test.ts:56-65 | No copy/state is defined for pagination exhaustion. A page that exactly equals `limitPerGroup` legitimately mints a `nextCursor` (per F5's own rule) even when nothing more exists — the next fetch correctly returns empty with no `nextCursor`, but the UI has no defined "end of results" moment, so one "More" click can silently do nothing. | Add a quiet "that's everything" affordance when `nextCursor` is absent after a fetch, and treat a subsequent empty page as silent exhaustion (no error/flash). |
| UU-9 | medium | api.search.tsx:21-49 (`Q_MIN=2`/`Q_MAX=200`, 400 `q_length`); search.ts:520 (`searchAll` only trims + slices to 200, no floor); plan.md:69 (Q4: loader calls `searchAll` directly) | `/search`'s loader calls `searchAll` directly per Q4, bypassing `api.search.tsx`'s length validation entirely. A 1-character query on `/search` will run live FTS/trgm legs across all groups with no specified UI state, while the same input to `/api/search` is a 400 `q_length` — an unreviewed behavioral split between the two entry points with no defined copy for the sub-minimum case. | Mirror `Q_MIN`/`Q_MAX` in the `/search` loader (or extract one shared validator both call), and define a "keep typing" state for sub-minimum-length queries instead of running search. |

## Evidence

- **Live probe (read-only, GET, house DSN):** `curl "https://lumen.abramhimmer.workers.dev/api/search?q=faith&limit=8"` on 2026-07-21 returned per-group hit counts `scripture:8, people:8, places:4, topics:8, episodes:8, art:8, words:8`. Six groups are at the requested limit (genuinely truncated, more rows exist); `places` returns its true total (4, nothing more exists). This directly falsifies the mockup's `results.length >= 4` threshold (build-mockup.py:276,279) as a "more exists" signal — it fires identically for both cases. Used as evidence for UU-1.
- **`build-mockup.py` script trace for UU-3:** the only DOM listeners wired in the script are on `#q` (input), `document` (keydown for `/`, `⌘K`, arrows), and `.sw` (theme swatches) — see lines 283-301. The `.scope` `<li>`/`<a>` elements built at lines 268-270 carry no click handler; their `href="#g-${key}"` is a plain in-page anchor jump. No `.scope` CSS rule uses `text-decoration:line-through` or any excluded/struck variant (full stylesheet scanned, lines 33-152). Confirms the "struck+faint" interaction named in plan.md:25 has no visual or behavioral precedent in the approved mockup.
- **Harness scan for UU-2/UU-4/UU-9:** `search.loader.test.ts` (full file, 141 lines) contains exactly one empty-`q` assertion (lines 69-73, "renders the empty state without calling searchAll") and asserts only `data.results === null` — no assertion on rendered content/copy. No test in this file or `api-search-cursor.test.ts`/`search-cursor-harness.test.ts` exercises `q` shorter than 2 characters, or any client-side re-fetch/debounce behavior.
- **`api.search.tsx:21-22`** defines `Q_MIN = 2; Q_MAX = 200;`, enforced at lines 43-49 (`badRequest("q_length", ...)`). **`packages/scripture/src/search.ts:520`** (`searchAll`) only does `(opts.q ?? '').trim().slice(0, 200)` — no minimum-length rejection anywhere in the shared search module. Since plan.md:69 (Q4) has the `/search` loader call `searchAll` directly rather than going through `api.search.tsx`, this floor is not inherited unless independently reimplemented.
- **`AppMenu.tsx:149-150`** comment: `// visual size-8 with a 44px hit box (after: overlay) — Emil touch rule`, implemented via `after:absolute after:-inset-2`. This is the codebase's own precedent for touch-target sizing on interactive chrome, absent from the scope-line spec.
- **`media.tsx:811-853`** and **`AppMenu.tsx:158-176`**: both existing interactive-chrome surfaces branch on `useIsMobile()` to swap a Popover/inline UI for a bottom `Sheet`; `SearchModal` in plan.md:24,37 has no analogous branch.
